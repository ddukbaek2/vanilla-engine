# 0.4.0

## Summary

- Names: renamed to the Rust conventions (Rust API Guidelines C-CASE). Functions, methods, variables, fields and modules are snake_case, enum values UpperCamelCase and associated constants SCREAMING_SNAKE_CASE.
- Same as the original vanilla.js: ported the general-purpose features that came into the original 0.4.0 (features moved from games, window stacking, loading and saving, input actions, the standard form of toon 3D, the shadow atlas) and its bug fixes with the same API. The folders now match the original too. (module paths are unchanged)
- Engine: graphics are usable anywhere. Scenes build GL resources with engine.get_graphic() in create, initialize, tick and async tasks. async/await is used like the original as well.
- The desktop now does what the browser used to: sound output moved from kira to the engine mixer on cpal, AVIF and HE-AAC decode, and word segmentation, fonts and Canvas2D set_font and put_image_data match Chrome.
- Scene and Engine: the original now also passes touches to widgets on nodes whatever the scene type, like the Rust version, so the two engines match. Fixed it, together with the original, so the view transform is applied before each scene draws.
- Docs: tools/apidoc (crate vanilla-engine-apidoc), which extracts the API data from doc comments, docs/api/0.4.0.json and the guide docs/guide/0.4.0/ko, en.
- Migration: where the public API changed, the line says so. (naming conventions, SoundSystem::new and its functions, Image::get_pixels, ScreenEffect::destroy, JsonAsset.load, FbxLoader names, ToonScreenOutline, toon shading)

## Changes

- A 3D color space setting (same as the original a803b71, in the style of Color Space: Gamma/Linear in Unity Player Settings): added EngineConfiguration::color_space and the enum ColorSpace (Gamma, Linear). The default is Gamma, and the screen is byte-identical to before. With Linear, toon 3D draws along the standard linear path. ToonRenderer::create_texture uploads color textures (base color, emission, decal, matcap, angel ring, ramp) as SRGB8_ALPHA8 so the GPU decodes them to linear (filtering and mipmaps in linear space), the shader no longer applies pow 2.2 to those textures, and passed colors (vertex color, tint, emissive color, decal color, outline color) are converted to linear with the standard sRGB curve (IEC 61966-2-1) before they are multiplied and mixed. Screen output, ToonPostProcess after tone mapping, the HDR shell outline and ToonScreenOutline line color, and the GLB base color (baseColorFactor into the vertex sRGB color) use the same curve. Data textures such as normals and masks are uploaded as plain RGBA8 with is_color_data: false in ToonTextureOptions (gamma does not distinguish them). With Linear, the 3D shaders the engine builds get #define VANILLA_COLOR_SPACE_LINEAR 1 (the shader text has the same two #ifdef paths as the original), and material chunks get toSurfaceColor(vec3), which converts an sRGB color into the space of ToonSurface.baseColor. ToonRenderer::new_with_options(ToonRendererOptions), ToonScreenOutline::new_with_options(ToonScreenOutlineOptions) and ToonPostProcessOptions::color_space take the color space (the default is the engine's value, Gamma without an engine, and new uses the engine's value) and report it with get_color_space. Added Engine::get_color_space and Graphic::get_color_space. Desktop GL does not enable GL_FRAMEBUFFER_SRGB on the default framebuffer (the shaders apply the curve themselves, as on the web canvas). 2D is composited in gamma space either way. Frames 5 and 40 of six toon examples (toonview, toonmaterial, toonpost, toonstyle, toonfx, toonshowcase) and the test scenes are byte-identical to before with Gamma. A capture test (tests/tooncolorspace.rs) runs the same checks as the original tooncolorspacechrome (texture encoding, the define line, the half mix at 127 for gamma and 188 for linear, the same values as the original, and engine defaults).
  - How to migrate: compose_toon_program_sources and ToonRenderer::read_material_program_sources take is_ambient_occlusion and color_space at the end (false and ColorSpace::Gamma to keep the old result). read_glb_arrays and read_glb_node_arrays take color_space: Option<ColorSpace> at the end (None means the engine's value). ToonScreenOutline::read_program_sources takes color_space and returns five (String, String). Graphic::new takes the color space as its third argument. ToonLineTarget::jump_flood_index is Option<usize> (see ambient occlusion below). Code that builds ToonTextureOptions or ToonPostProcessOptions by listing every field adds is_color_data or color_space, or uses ..Default::default().
- Toon ambient occlusion (same as the original 61a68fa, screen-space AO, GTAO: Jimenez, Wu, Pesce, Jarabo 2016, applied only to indirect light like Unity URP SSAO): added ToonPostProcess::set_ambient_occlusion(is_enabled, intensity, radius, resolution_scale, direct_lighting_strength), get_ambient_occlusion (ToonAmbientOcclusion), is_ambient_occlusion_enabled, draw_ambient_occlusion(gl, line_target, view_matrix, projection_matrix), get_ambient_occlusion_texture, get_ambient_occlusion_prepass(gl) and draw_ambient_occlusion_with_prepass, ToonRenderer::set_ambient_occlusion_texture, get_ambient_occlusion_texture, ToonDrawQueue::set_post_process and has_post_process. The three shaders (GTAO, horizontal blur, vertical blur with upsampling) are the original text as is. Normals and depth reuse the screen outline's line target, and scenes without outlines draw only the line target with no lines (ToonScreenOutline skips seeds and flooding when both outline and crease widths are 0, and draw_outline draws nothing). ToonDrawQueue computes it after the line target and before bodies, sets it on the renderer and clears it after end_frame. The body shader switches to a body program with TOON_AMBIENT_OCCLUSION defined (sharing the default outline and shadow depth programs, falling back to the default when it cannot be built) and multiplies the visibility at the screen position into the ambient light. The texture unit is 16. The original uploads the origin in the ambientOcclusionOrigin field of the ToonFrame frame block; Rust has no frame block yet and uploads the same value in a uniform with the same name. With it off, bodies use the default body program, so the screen is byte-identical to before. A capture test (tests/toonambientocclusion.rs) draws the same scene as the original toonambientocclusionchrome (room corner, crate, robot) with the same checks, and the measured darkening (wall corner, left corner, beside the crate, under the robot's feet) equals the original to the first decimal. Between the two engines (640 x 360), 55 pixels differ when on in perspective, 6 in orthographic and 25 to 140 in the AO texture, by 1 to 2.
  - How to migrate: ToonLineTarget::jump_flood_index is Option<usize> (None when nothing was flooded, the original uses -1). Games that used a zero-width outline (set_width(0) and crease width 0) will see that screen change.
- Direct lighting strength for toon ambient occlusion (same as the original 50cb8de, in the form of Direct Lighting Strength in Unity URP SSAO and HDRP ScreenSpaceAmbientOcclusion.directLightingStrength): added the fifth argument direct_lighting_strength of set_ambient_occlusion (0 to 1, default 0 in the original), get_ambient_occlusion_direct_lighting_strength (post process and renderer), ToonAmbientOcclusion::direct_lighting_strength and the second argument of ToonRenderer::set_ambient_occlusion_texture. - Streaming audio loading (same as the original AudioLoadType, the form of Unity's AudioClip Load Type and Unreal's sound wave streaming): AudioAsset gains the load type AudioLoadType (Automatic, DecompressOnLoad, Streaming) with set_load_type, get_load_type, is_streaming, get_stream_url, and the threshold AUTOMATIC_STREAMING_BYTE_THRESHOLD (1 MiB). Until now every sound was fully decoded to PCM, so one 3 minute stereo background track held about 61 MiB (f32). The default stays full decoding (DecompressOnLoad) as in the original, and only assets set to Automatic stream files larger than 1 MiB (the file size on desktop, the response Content-Length on the web). The engine SoundSystem sound row (SoundRow) gains a load_type field; when it is None, background music (is_music) uses Streaming and sound effects use DecompressOnLoad. Desktop: a streaming asset holds only the compressed source (a file path or bytes in memory) and the trim plan (opening demuxes the file once), and when played, a decoder thread per player decodes chunk by chunk into a ring buffer (16384 frames, 128 KiB for stereo) that the mixer's streaming source reads (nothing is decoded on the audio thread). Packet reading, Chrome's start and end trimming, the SincResampler and the speaker rules are the same code as full decoding, so the produced samples are bit-identical to the fully decoded buffer (27 test formats), and the streaming source computes like the buffer source, so playback, the end, the loop seam, a start position, stopping, playback rate and a different device sample rate produce bit-identical output. Looping reopens the decoder at the end and writes the next pass right after, without a gap, and a start position (set_time) decodes from the start and discards up to it. When the ring runs dry it outputs zeros meanwhile and the position follows the context clock. The duration (get_duration) is the length the container reports (the same as full decoding for the MP3, AAC, FLAC, WAV and Ogg test files; WebM, whose blocks carry no duration, can differ by about 4 milliseconds (-68 to +177 frames)) and becomes the decoded length once the sound has been decoded to the end. Web: as in the original, an HTMLAudioElement is connected to the player's GainNode through a MediaElementAudioSourceNode (one media element per player, the pitch follows the playback rate, other origins use CORS, sounds loaded from memory use a blob: URL). When the context is suspended the media element pauses and resumes with it, get_time is the media element's position, and background music faded out by SoundSystem stops when the fade ends. Measured (Mac mini M2 Pro, 3 minute stereo AAC of 2.92 MB, release optimization): full decoding loads in 107 ~ 125 ms and holds 63,504,000 bytes of PCM; streaming loads in 1.6 ~ 1.8 ms (demux only) and holds a 131,072 byte ring, playing from the start takes 0.7 ~ 1.0 ms (one ring fill), and playing from 150 seconds takes 0.03 ms (the decoder thread decodes from the start and discards up to that point, so the sound starts that much later; that delay was not measured). The original on a real device (iPhone SE2) loaded in 137 ms against 8,618 ms for full decoding.
  - Migration: background music played through SoundSystem streams when load_type is absent, so code that used that asset's get_audio_buffer() directly sets the sound row's load_type to Some(AudioLoadType::DecompressOnLoad). Code using AudioAsset directly keeps the same default and needs no change; to stream, call set_load_type(AudioLoadType::Streaming). A streaming asset's get_audio_buffer() is None. Code that builds SoundRow as a struct literal adds load_type: None. On desktop get_stream_url is the file path when loaded from a file and None when loaded from memory (on the web it is the URL or a blob: URL as in the original).

- ToonScreenOutline: rebuilt the screen-space outline in the standard form of real-time toon rendering. (Same shaders and values as vanilla.js)
  - Detection: in the line buffer (normal, line id, depth), each edge between a pixel and its four direct neighbors is tested once, and the line is placed at the middle of that edge. Until now crease lines were judged from the normal at a single point creaseRadius away, so both sides of a crease formed bands, and half-size buffers produced dotted lines, parallel second lines, and bands inside the silhouettes of curved surfaces
  - Depth: reconstructs two neighboring pixels to view-space positions and detects occluded silhouettes by their distance from each other's tangent plane. Twice the pixel size at that depth is added to the threshold
  - Widening: propagates the distance to edge segments with jump flooding. (log2 steps, outline and crease lines separately) The 3-pixel radius limit is gone
  - Blending: each pixel of the drawing area is covered by clamp(width / 2 - distance + 0.5, 0, 1) from the distance to the nearest edge. Lines do not break even with a reduced line buffer

  - How to migrate (the public API changed)
    - set_crease(angle, intensity, continuation pixels) → set_crease(angle, width, intensity). Width is in the units of set_width, intensity is 0 ~ 1. Continuation pixels are gone. A look similar to the old set_crease(60.0, 0.5, 2.0) is set_crease(60.0, 1.0, 0.8) in pixel units, and in world units a width of about half the outline width (set_crease(60.0, 0.011, 0.8) for set_width(0.022, World)). Since the width is in the units of set_width, giving 1 in world units makes the line 1 meter wide
    - set_depth_threshold(depth threshold, contact threshold) → set_depth_threshold(depth threshold). Its meaning changed to tangent plane distance. The contact threshold is gone
    - Meaning of set_width: the width of one line, half on each side of the edge. Default 1.5 → 2 pixels. To match the outer thickness of the old look, give twice the value.
